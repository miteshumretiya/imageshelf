Real problems found while building and testing ImageShelf. Add a row each time you find and fix a problem, and commit each fix separately with a message such as `fix: …` so the Git history shows the correction.

| D1 | The Shelf view showed thumbnails as thin cropped strips, with no file names under them. | `setUniformItemSizes(True)` made the view calculate every item's size once, from the first item, before its thumbnail and text were available. | Removed `setUniformItemSizes(True)`, so each item is measured properly. | Rescanned `sample_images` and checked the shelf screenshot. | Fixed: full thumbnails with names. |
| D2 | The automated test suite froze about 1 run in 4 (always in a controller test). | PyQt's `QSignalSpy.wait()` keeps Python's GIL while it blocks. The worker thread needed the GIL to finish emitting its `finished` signal, so the two threads waited on each other (deadlock). | Wrote `SignalCatcher` in `tests/conftest.py`, which waits by calling `processEvents()` from Python and so releases the GIL. | Ran the full suite 10 times in a row. | Fixed: 10/10 runs pass (109 tests). |
| D3 | The benchmark froze at the first multi-process run on Linux. | On Linux, Python starts worker processes with `fork()`, which copies Qt's internal locks in a locked state into the child. | Created the process pool with the `spawn` start method (the default on Windows and macOS). | Re-ran `benchmark.py`. | Fixed: completes on all platforms. |
| D4 | The "pure-Python" benchmark workload ran 1.9× faster with 2 threads, which should not happen for GIL-bound code. | About half of that workload's time was JPEG decoding inside Qt (C++), which releases the GIL, so it was not really pure-Python work. | Made the workload mostly Python (brightness, contrast and histogram loop over a 1000×750 copy). | Re-ran the benchmark. | Fixed: threads ≈1.05× vs processes ≈1.5×, as GIL theory predicts. |
| D5 | The app crashed at start-up in a Linux environment with no sound server. | Qt's PipeWire audio backend crashes when no audio service is running. | Documented the `QT_AUDIO_BACKEND=pulseaudio` workaround in the README; the tests set it automatically on Linux. | Ran the app and the tests on the same machine. | Workaround works. |
| D6 | On Windows, `python main.py sample_images` did not open a window, although `python -m pytest -v` passed (109 tests). | The commands were run from the parent folder (`Documents\imageshelf`, where the venv is) instead of the project folder that contains `main.py`. Python stopped with `can't open file ... main.py` (exit code 2) before Qt started, and `make_sample_images.py` failed the same way, so `sample_images` was never created. pytest still passed because it searches sub-folders and `conftest.py` adds the project folder to `sys.path`. QtMultimedia was not the cause: run with `-X faulthandler` from the project folder, the window, `QMediaPlayer`, `QAudioOutput` and `QSoundEffect` all worked with both the `ffmpeg` and `windows` media backends. | Ran every command from the project folder. Added a line to the README Setup section saying so, and a Troubleshooting entry for this symptom. No code change was needed. | From the project folder: `python tools/make_sample_images.py sample_images`, then `python main.py sample_images`. Checked the window by eye and pressed F5 to listen for the chime. | Fixed: the window opens with 17 thumbnails (2 unreadable files, 2 duplicate groups) and the chime plays. |
| D7 | `python benchmarks/benchmark.py` stopped after 2 s with `ValueError: Not a readable image (Unsupported image format)` and did not write `benchmarks/results.md`. | `big_images` was made with `make_sample_images.py big_images --big 60`, which also adds the small test set, including the deliberately damaged `photos/broken.jpg` and `photos/empty.png`. The benchmark timed every file and stopped at the first unreadable one. | The benchmark now skips files that `read_image_info` rejects (the same check the app uses for its Errors tab) and prints which ones it skipped. | Re-ran `python benchmarks/benchmark.py` on the same `big_images` folder. | Fixed: 2 files skipped, 77 images timed; it finished in about 140 s and wrote `results.md`. |
| D8 | With no Qt multimedia backend (simulated by hiding `plugins/multimedia` in the PyInstaller build), "Choose music…" still showed "♫ slideshow_music.wav", but the slideshow was silent and nothing told the user why. | Without a backend `QMediaPlayer` is "not available" and fails silently: it never emits `errorOccurred`, so the existing "Music cannot be played" message never appeared. | `PreviewPanel` checks `QMediaPlayer.isAvailable()` at start-up. If it is false, it disables the music button and volume slider and shows "Music is not available on this computer…". The slideshow and the completion chime (`QSoundEffect` does not need the backend) are unchanged. | Ran the app with the multimedia plugins hidden (from source and as the packaged exe), then normally. | Fixed: without a backend the app opens and scans, the music controls are disabled with the message, and the slideshow and chime still work. With the backend, music plays as before. |
